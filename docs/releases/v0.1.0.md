# v0.1.0 — first frozen compiler milestone

Date: 2026-09-04

Release candidate base: `91c861a2fa72d3bada7f8d4787e83f7902ec4f2e`

`v0.1.0` freezes the first complete, correctness-first CPU compiler vertical slice. The milestone is intentionally compact: it demonstrates real IR verification, lowering, memory planning, explicit loop semantics, code generation, native compilation, and reusable execution without pretending to be a production tensor framework.

## What this milestone proves

The repository now owns the whole path from a small Python tensor frontend to executable native code:

```text
Python expressions + static typed inputs
-> typed tensor IR
-> verification
-> optimization passes
-> virtual-buffer IR
-> liveness-based physical memory planning
-> explicit loop/kernel IR + broadcast maps
-> verifier-backed fusion
-> deterministic generated C11
-> GCC / Clang / MSVC shared library
-> reusable native executable
```

A separate NumPy reference executor remains available for differential correctness checks.

## Release highlights

- Explicit, statically typed tensor values and external inputs.
- Deterministic verifier-backed IR transformations.
- Conservative optimization passes that preserve integer overflow and floating-point edge semantics.
- Explicit memory planning rather than implicit NumPy temporaries.
- Explicit broadcast index maps and loop iteration semantics.
- Bounded integer fusion with alias/liveness guards.
- Deterministic C11 backend for POSIX-like GCC/Clang toolchains and Windows MSVC.
- Native artifact reuse in-process and through an optional persistent cache.
- Reusable `NativeExecutable` handles and optional preallocated output buffers.
- Conservative flat-loop vectorization hints plus guarded SSE2 specializations for selected contiguous `int32` kernels.

## Validation

The release candidate base passed GitHub Actions CI run `33828947201` on the exact commit above. The CI matrix runs:

- Ubuntu, Python 3.11
- Ubuntu, Python 3.13
- Windows, Python 3.11
- Windows, Python 3.13

Each job installs the package with development dependencies, runs `ruff check .`, and executes the pytest suite.

The release-preparation PR must pass the same matrix before merge. Documentation and benchmark harness changes in that PR are not allowed to alter compiler semantics.

## Deliberate non-goals

This release does **not** claim dynamic shapes, multiple returned tensors, zero-copy input aliasing, generalized SIMD lowering, general DAG fusion, parallel scheduling, GPU/CUDA execution, or production-framework compatibility.

Those are future milestone candidates, not missing pieces required to call the first vertical slice complete.

## Maintenance after release

The `v0.1.x` line should operate in sentinel/maintenance mode:

- fix reproducible correctness or portability regressions;
- repair CI failures;
- strengthen tests around independently provable gaps;
- improve diagnostics or release quality when bounded and justified;
- otherwise no-op.

Do not generate PRs merely to enumerate additional opcode × dtype × fusion-shape SIMD combinations. A generalized SIMD abstraction or another major capability should be selected explicitly as a later milestone.

## Reproducible performance checks

`benchmarks/v0_1_cpu.py` provides a small, intentionally non-CI benchmark harness for comparing the semantic reference path, the explicit loop interpreter, and warm native execution on the same `int32` add tree. It also reports one eager native compilation time. Results are machine/compiler dependent and should be recorded with platform/compiler metadata rather than treated as universal project claims.
